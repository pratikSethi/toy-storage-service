# Build plan

Commit by commit. Each commit leaves a runnable system. Done steps carry their commit hash.

1. **Docs.** PRD, system overview, ADRs, backlog, this plan. Done, `f332510`.
2. **Scaffold.** `Makefile`, Cargo workspace (`frontdoor`, `ts2-core`), multi-stage `Dockerfile` that works with docker and podman, compose with FrontdoorService only, `mkdocs.yml` with the Material theme. Done, `57cc01a`.
3. **`ts2-core`.** Manifest model, the async `ObjectIndex` and `ChunkStore` traits, the SQLite and local-disk implementations (tmp, write, fsync, rename, fsync parent dir, `tmp/` cleared at startup), put and get with whole-chunk reads and checksum verification. Done, `5a08d40`.
4. **FrontdoorService v0.1.** Health, bucket CRUD, object PUT/GET/HEAD/DELETE/list, range GET, streaming `max_object_bytes` with axum's default body limit disabled, utoipa 5.x OpenAPI 3.1 and Scalar, RFC 9457 errors, request ids, JSON logs, compose healthcheck and data volume, curl demo. Done, `3f0efb0`.
5. **Python CLI and e2e smoke.** `cli/` with typer and httpx (generated client for JSON, plain `httpx` for object bytes), `tests/e2e/` with a smoke test through the CLI against a throwaway frontdoor (`make e2e`). Done. The CLI uses plain `httpx` throughout, not a generated client.
6. **Observability profile.** OTel Collector (`otlphttp` exporters), VictoriaMetrics, VictoriaLogs, Grafana with one FrontdoorService dashboard, behind `--profile obs`. Done, `14b88b9`. The ObjectIndex backup job for the SQLite file is still open.
7. **Proto and C++ scaffold.** `proto/ts2/v1` for the ChunkStoreService and ObjectIndexService calls, a CMake and vcpkg setup with Catch2, a Docker stage for C++, and CI that builds and tests every component. The Rust traits are already async and chunk-granular, so FrontdoorService changes mostly its client. The trait gains a node id and a few error variants, see step 11. Done, `139acef`.
8. **Round 4, contracts and plumbing (step 0).** One owner, one commit series, before anything forks. Renamed the duplicate `NodeInfo` messages, closed the contract gaps from [review 002](reviews/002-round3-review.md) (1 MiB frames, id format, checksum sidecar, error codes, paging limits, `ListChunkRefs`, `previous` on `PutManifestResponse`), shared `cmake/ts2_proto.cmake`, root `vcpkg.json` with a pinned baseline, asan preset, `.dockerignore`, CI cache and concurrency fixes, and the `ts2-proto` Rust crate. Workers (a) and (b) must not edit `proto/`, `ci.yml` or the shared CMake file; they raise a question instead.
9. **Round 4 (a), ChunkStoreService.** C++ with gRPC (`chunk-store/`), `put`, `get(range)`, `delete`, `list`, sidecar checksums, graceful SIGTERM shutdown. Runs in parallel with (b), touching only `chunk-store/` and its own row in `docs/ports.md`. The per-request token stays in v0.2. Done, `e7af98e`. A put fails with `RESOURCE_EXHAUSTED` when free space is below the chunk size; a separate full-disk threshold is not built.
10. **Round 4 (b), ObjectIndexService.** C++ with SQLite (`object-index/`): manifests, listing, all four bucket RPCs, and `ListChunkRefs`. Parallel with (a). Done, `a39e072`. Its schema is written separately from the Rust one, which stays as the single-binary stand-in.
11. **Round 4 (c), FrontdoorService switches to gRPC.** After (a) and (b). tonic clients (from `ts2-proto`) in `ts2-core` behind the existing traits, with an in-process fake gRPC server for its tests. The `ChunkStore` trait gains a node id and a list method, `Error` gains unavailable, timeout and disk-full variants, chunk id validation is tightened to 32 lowercase hex, and orphan GC runs in frontdoor. Both C++ services join compose and `make e2e` runs against them.
12. **Placement over 3 nodes (v0.2).** `hash(chunk_id) mod N` in `ts2-core`, three ChunkStoreService nodes in compose, API key auth.
13. **Second cell and replication (v0.4).** Two cells in compose, R=3, the bucket-to-cell map, failure drills.

Docs are served locally with `mkdocs serve` and published to GitHub Pages once the repo is public.
