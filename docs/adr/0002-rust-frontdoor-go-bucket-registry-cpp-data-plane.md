# ADR 0002: Rust FrontdoorService, Go BucketRegistryService, C++ data plane

Status: accepted. The Rust, C++ and Python parts are built. The Go and TypeScript parts are not built.

> **Terms used here.** Defined once, so this page reads on its own.
>
> - **cell**: one ObjectIndexService plus its ChunkStoreService nodes. It is the unit a fault is meant to stay inside. One cell exists today.
> - **gRPC**: a way for services to call each other over the network (a remote procedure call, RPC), sending Protobuf messages over HTTP/2. The TS2 services talk to each other this way.
> - **fsync**: a system call that forces written data onto the disk before it returns, so a crash cannot lose it.
> - **SQLite**: a small database that lives in one file.
> - **ADR** (architecture decision record): a short note on one decision and why it was made.

## Context

TS2 has three kinds of code: a request-heavy edge that streams bytes, a bucket registry (buckets, tenants, quotas, bucket-to-cell map) that is mostly CRUD and background reconciliation, and a data plane that does disk I/O and owns on-disk formats. The builder also wants to learn each language in a setting that suits it.

## Decision

- **FrontdoorService: Rust** (axum, tonic, tower, utoipa 5.x). Chunking, hashing and placement live in the library crate `ts2-core`. Streaming bytes with no garbage collector pauses, and tower gives admission and load-shedding layers.
- **BucketRegistryService: Rust module first, Go service from v0.4.** Until v0.4 it is an in-process module of FrontdoorService called `BucketRegistry`, behind a trait of the same name. In v0.4 it moves to its own Go service (`bucket-registry/`, stdlib `net/http` or chi, gRPC server). Fast to write for CRUD and reconcile loops.
- **`ts2` CLI: Python** (typer and httpx, with a client generated by openapi-python-client from `docs/api/openapi.yaml`), installed with `uv tool install`. It lives in `cli/` and shares uv tooling with the e2e tests. It uses the generated client for JSON calls and plain `httpx` for object bytes, because the generated client buffers bodies in memory. A Rust rewrite of the CLI, sharing types with FrontdoorService, is parked until distribution (a single static binary) or multipart upload throughput needs it.
- **ObjectIndexService and ChunkStoreService: C++** (CMake, vcpkg, Catch2; SQLite first, RocksDB later). Direct control of file I/O, fsync behavior and on-disk layout.
- **Tests: Python** via uv (pytest, httpx) for end-to-end. **UI: TypeScript**, later.
- **Internal contract:** Protobuf over gRPC in `proto/ts2/v1`. **External contract:** OpenAPI 3.1, generated from FrontdoorService's code.

**Today:** FrontdoorService (Rust), ObjectIndexService and ChunkStoreService (C++), the CLI and the end-to-end tests (Python) exist. Not built: there is no `bucket-registry/` directory and no Go code, so no BucketRegistryService and no in-process `BucketRegistry` module either. Bucket operations live in ObjectIndexService (remote mode) and in `ts2-core`'s SQLite index (single-process mode). Also not built: the TypeScript UI, RocksDB, and a client generated by openapi-python-client (the CLI uses plain `httpx` throughout).

## Consequences

- Four toolchains in one monorepo (Rust, Go, C++, Python), and TypeScript later. `make` is the only entry point and dispatches per component.
- Each component is built and tested in isolation, one component per commit.
- Protobuf definitions are the shared source for Rust, Go and C++ stubs. The CLI and e2e tests use only the OpenAPI spec.
- The CLI needs Python and uv on the user's machine, and is slower for large transfers than a native binary would be. That is the cost of the parked Rust rewrite.
- More setup cost than a single-language build.

## Alternatives considered

- **All C++.** Simplest toolchain, but weaker for web and CRUD work.
- **All Rust or all Go.** Simpler, but the C++ data plane is a learning goal.
- **C++ FrontdoorService.** Rejected: Rust gives memory safety on the network-facing edge.
- **Go CLI.** The original plan. Replaced by Python to reuse the OpenAPI-generated client and the uv toolchain already used for e2e tests.
- **Rust CLI now.** Parked, see above.
